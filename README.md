# Учёт рабочего времени

Небольшое веб-приложение: сотрудники, таймер с описанием задачи и отчёт по каждому сотруднику за выбранный период. Данные лежат в SQLite и сохраняются после перезапуска.

Стек: .NET 10, ASP.NET Core Minimal API, EF Core + SQLite, одна HTML-страница на чистом JS. Тесты на xUnit и WebApplicationFactory.

## Запуск

Нужен [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0).

```bash
dotnet run --project src/TimeTracker --launch-profile http
```

Открыть http://localhost:5197. Файл базы `timetracker.db` создаётся рядом с проектом при первом запуске.

Тесты:

```bash
dotnet test
```

## Что умеет

- добавить сотрудника;
- запустить таймер с описанием задачи и остановить его. У сотрудника может быть только один запущенный таймер, повторный старт возвращает 409 и не создаёт вторую запись;
- отчёт за период: записи каждого сотрудника и итог. Запись, которая переходит через границу периода, считается только той частью, что попала в период. Запущенный таймер считается до текущего момента. Если записей нет, отчёт показывает сотрудников с нулём;
- после перезапуска всё на месте, включая запущенные таймеры.

API:

| Метод | Путь | |
|---|---|---|
| GET | `/api/employees` | сотрудники и их запущенный таймер |
| POST | `/api/employees` | `{ "name": "..." }` |
| POST | `/api/employees/{id}/timer/start` | `{ "task": "..." }`, 409 если уже запущен |
| POST | `/api/employees/{id}/timer/stop` | 409 если таймер не запущен |
| GET | `/api/report?from=...&to=...` | период `[from, to)` в ISO 8601 |

## Устройство

Весь бэкенд в двух файлах: `AppDb.cs` (модель и настройки EF) и `Program.cs` (эндпоинты). Отдельных слоёв, репозиториев и сервисов нет, для такого объёма они только добавили бы кода. Схема создаётся через `EnsureCreated`, без миграций: если приложение будет развиваться, первым делом стоит перейти на миграции.

Время хранится в UTC. Границы дней для отчёта считает браузер в своём часовом поясе, поэтому «с 30.10 по 30.10» в Бишкеке и в Москве даст разные интервалы UTC, как и должно быть.

Текущее время берётся из `TimeProvider`, в тестах он подменяется ручными часами. Поэтому тесты не ждут реальные минуты и не зависят от того, когда их запустили.

Примеры запросов:

> Вот тестовое задание [текст]. Разбери, что они хотят проверить, кроме явных пунктов. Какие граничные случаи тут есть?

> Сделай на .NET 10 Minimal API + EF Core SQLite + одну HTML-страницу без фреймворков. Без слоёв и репозиториев, весь API в Program.cs.

> Что будет, если два запроса на старт таймера придут одновременно? Проверка через AnyAsync перед вставкой это не закрывает, нужна защита на уровне БД.

## Ошибки, которые нашёл и исправил

**1. Двойной старт таймера при гонке.** Первая мысль, проверить «есть ли запущенный таймер» и потом вставить запись, не работает при двух одновременных запросах: оба проходят проверку и создают две записи. Исправил частичным уникальным индексом `UNIQUE (EmployeeId) WHERE EndedAt IS NULL`. Теперь второй запрос получает ошибку от базы, а API превращает её в 409. Тест `Concurrent_starts_create_only_one_entry` шлёт 10 параллельных стартов; без индекса он стабильно падает.

**2. Время терялось на часовой пояс.** SQLite не хранит `DateTimeKind`. EF читает время обратно как `Unspecified`, в JSON оно уходит без `Z`, и браузер принимает UTC за локальное. В Бишкеке таймер, запущенный в 14:43, показывался бы как 08:43. Исправил конвертером в `AppDb.ConfigureConventions`, который помечает прочитанное время как UTC. Тест `Times_are_returned_as_utc` без конвертера падает.

**3. Запись через полночь попадала в отчёт целиком.** Если запись началась в 23:00 и закончилась в 01:00, простой фильтр по дате старта отдавал все 2 часа одному дню и 0 следующему. Теперь в отчёт попадают все записи, которые пересекают период, и длительность обрезается по его границам. Тест `Entry_crossing_period_border_is_clipped`.

**4. «По» в отчёте не включало последний день.** Если передать в API `to = 30.10 00:00`, сам день 30.10 в отчёт не попадает. Страница прибавляет к дате «по» один день, а API работает с полуоткрытым интервалом `[from, to)`, чтобы граница не считалась дважды.

## Тесты

15 тестов в `tests/TimeTracker.Tests/ApiTests.cs`, каждый поднимает приложение на отдельном временном файле SQLite:

- полный цикл: сотрудник, старт, стоп, время в отчёте;
- повторный старт: 409, запись одна и с первой задачей;
- 10 одновременных стартов: создаётся ровно одна запись;
- старт после стопа работает, итог складывается из двух записей;
- стоп без запущенного таймера: 409;
- пустой отчёт без сотрудников и пустой отчёт за период без записей;
- запущенный таймер считается до текущего момента;
- запись через границу периода обрезается;
- данные на месте после перезапуска приложения;
- время в ответах API с `Z`;
- валидация пустых имени и задачи, неизвестный сотрудник, перевёрнутый период.
